# 국내 기준 연결을 읽는 법

리포트의 **국내 기준** 줄은 "이 문제는 이 기준의 이 조항과 관련 있다"는 연결입니다. 인증 심사나 법적 판단의 결과가 아니라 **참고용 연결**입니다.

검수 상태는 세 가지입니다.

| 표시 | 뜻 |
|---|---|
| `원문 대조함: <누가>, <날짜> · 전문가 검수 전` | 공식 원문과 조항 번호·이름·문구를 대조했지만, 전문가가 보지는 않은 상태 |
| `전문가 검수함: <누가>, <날짜>` | 전문가가 연결이 맞는지까지 확인한 상태 |
| `검수 전 (원문 대조 안 함)` | 초안. 원문과 대조하지 않았으니 믿지 마세요 |

- 지금 들어 있는 14개 항목은 모두 "원문 대조함"입니다. 대조한 쪽은 **AI(Claude)** 이고, 공식 자료의 조항과 맞는지만 봤습니다. 전문가 검수는 아직 받지 않았습니다. 그래서 리포트에는 `원문 대조함: Claude (AI), 2026-11-04 · 전문가 검수 전`처럼 나옵니다. 검수자 자리의 `Claude (AI)`는 AI가 원문과 대조했다는 뜻입니다.
- `기준 정보 없음 (검수 전)`은 규칙이 가리키는 기준 ID가 `mappings/`에 없다는 뜻입니다.
- 항목이 14개로 적은 것은 확실히 이어지는 것만 남겼기 때문입니다. 모든 결과에 국내 기준이 붙지는 않습니다 (예: `NX-001`은 일부러 연결하지 않았습니다).
- 일부 연결에는 조건이 붙지만 리포트는 그 조건을 보여 주지 않습니다. `ISMS-P 2.7.2 암호키 관리`는 노출된 값이 실제로 암호키(개인 키, 서명 비밀 등)일 때 해당하고, 일반 API 토큰에는 연결이 약합니다. `안전성 확보조치 기준 제6조 제3항`은 테이블에 개인정보가 들어 있을 때 해당합니다. 안전성 확보조치 기준의 모든 항목은 개인정보처리자에게 적용됩니다. 어느 사업자에게 어떤 고시가 적용되는지는 판단하지 않았습니다.
- **법률 자문이 아닙니다.** 최종 판단은 전문가와 확인하세요.

`--rules-dir`로 직접 만든 규칙 폴더를 쓰면 내장 데이터를 **통째로 대체**합니다. 그 폴더에 `mappings/`(안에 `kinds.yaml` 포함)도 함께 두어야 합니다. 없으면 규칙의 국내 기준이 모두 "기준 정보 없음 (검수 전)"으로 나오고 터미널에 경고가 뜹니다(점검은 그대로 진행됩니다). 다만 `kinds.yaml`로 이어지는 연결(비밀 키, 취약한·KEV 라이브러리, Supabase RLS `SB-001`, 자산)은 `mappings/`가 없으면 경고 없이 **국내 기준 부분이 통째로 빠집니다.** `kinds.yaml`까지 포함해 `mappings/`를 복사해 두면 피할 수 있습니다. `mappings/` 파일 형식이 잘못되면 종료 코드 2로 멈춥니다.
