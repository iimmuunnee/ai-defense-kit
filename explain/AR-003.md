이 저장소의 개발 컨테이너 설정(`devcontainer.json`)에 컨테이너를 만들거나 시작할 때 실행되는 명령이 있습니다. 근거에 필드 이름(`onCreateCommand`, `updateContentCommand`, `postCreateCommand`, `postStartCommand`, `postAttachCommand` 중 하나)과 값을 보여 드렸습니다. 문자열이 아니면 JSON 그대로 보여 드립니다.

왜 확인해야 하나요?
Dev Containers 참조 문서에 따르면 이 명령들은 컨테이너 안에서 실행됩니다. `onCreateCommand`, `updateContentCommand`, `postCreateCommand`는 컨테이너가 만들어질 때 차례로 실행되고, `postStartCommand`와 `postAttachCommand`는 컨테이너를 시작하거나 연결할 때 실행됩니다. 하나가 실패하면 뒤의 스크립트는 실행되지 않습니다.

컨테이너 안에서 이 명령이 무엇에 접근할 수 있는지는 컨테이너 설정의 나머지에 달려 있는데, 이 점검은 그것을 보지 않으므로 판단하지 않습니다. 명령이 해로운지는 이 점검이 판단하지 못해서 확신도를 "의심"으로 표시했습니다.

어떻게 하나요?
1. 근거의 명령이 무엇을 하는지 읽어 보세요. 내려받아 실행하는 명령, 알 수 없는 주소, 난독화된 코드가 보이면 컨테이너로 열지 마세요.
2. 같은 파일에 `initializeCommand`가 있다면 그것은 호스트 머신에서 실행되므로 따로 알려 드립니다(AR-002).

이 점검은 파일의 글자만 읽고 아무것도 실행하지 않습니다. 근거가 "파일을 해석하지 못했습니다"로 나오면 파일이 깨졌거나 1MB보다 크거나 심볼릭 링크라서 읽지 않은 것이니 직접 열어 확인하세요.

근거에 `****`가 보이면 비밀 값처럼 보이는 부분을 가린 것입니다. 실제 명령은 이 도구가 아닌 일반 텍스트 편집기로 파일을 열어 직접 확인하세요.
가리는 것은 gitleaks가 키로 알아본 값, URL 안의 비밀번호, 개인 키처럼 보이는 블록입니다. adk가 키로 알아보지 못한 값은 명령에 그대로 보입니다(예: `--password 값`). 그래서 이 리포트를 비밀 점검으로 쓰지 마세요. 비밀 값은 secrets 점검이 따로 찾습니다. `env` 안의 값은 이름에 token, password, key 같은 단어가 있으면 가립니다. 명령 문장이 섞여 있는 값은 키처럼 보여도 가리지 않습니다.
`-----BEGIN ... PRIVATE KEY-----`로 시작하는 블록은 진짜 키인지 따지지 않고 END 줄까지, END 줄이 없으면 그 값의 끝까지 통째로 가립니다. 그 자리에 가렸다는 문구가 나오고 등급은 "높음", 확신도는 "의심"이 됩니다. 이 안에 명령이 숨어 있을 수 있으니 파일을 직접 확인하세요.
근거가 길면 앞부분만 보여 주고 `… (잘림, 파일을 직접 확인하세요)`를 붙입니다. JSON 안에서 명령이 아닌 긴 값은 `…(잘림)`으로 줄입니다. 그때는 파일을 직접 열어 나머지를 확인하세요.
