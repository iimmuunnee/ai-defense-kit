로그인하거나, 셸을 열거나, 정해진 시각마다 무언가를 실행하게 하는 지점이 `adk device init` 때 기록한 기준값과 다릅니다. 근거에는 파일 경로와 무엇이 일어났는지(추가됨, 사라짐, 바뀜)만 나오고 파일 내용이나 줄은 나오지 않습니다. 셸 시작 파일에는 토큰을 적어 두는 경우가 많기 때문입니다.

보는 지점
- macOS: `~/Library/LaunchAgents`, `/Library/LaunchAgents`, `/Library/LaunchDaemons`의 `*.plist`
- Linux: `~/.config/systemd/user`의 유닛 파일(한 단계 아래 `*.wants` 같은 폴더 포함), `~/.config/autostart`의 `*.desktop`
- 크론: `/etc/crontab`, `/etc/cron.d`의 파일, `/usr/bin/crontab -l`로 읽은 사용자 크론
- 셸 시작 파일: `~/.zshrc`, `~/.zprofile`, `~/.zshenv`, `~/.zlogin`, `~/.bashrc`, `~/.bash_profile`, `~/.bash_login`, `~/.profile`, `~/.config/fish/config.fish`

등급: 셸 시작 파일은 보통, 나머지는 높음입니다. 셸 시작 파일은 사용자가 자주 고치지만, 다른 지점은 설치 프로그램 말고는 바뀔 일이 드뭅니다.

왜 확인해야 하나요?
악성 패키지나 확장 프로그램은 한 번 실행된 뒤에도 계속 남으려고 이런 지점에 자기 명령을 넣습니다. 그러면 컴퓨터를 다시 켜거나 터미널을 열 때마다 다시 실행되어, 지운 뒤에도 자격 증명을 계속 가져갈 수 있습니다.

이 점검이 보지 못하는 것: 위 목록에 없는 지점(로그인 항목, 브라우저 확장, 편집기 확장, `/etc/profile.d` 등), 점검 사이에 넣었다가 지운 변경, 기준값을 만든 때 이미 들어 있던 명령, 관리자 권한으로 숨긴 것.
