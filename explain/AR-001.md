이 저장소의 `.vscode/tasks.json`에 자동으로 실행하도록 정해 둔 VS Code 작업이 있습니다. `runOptions`의 `runOn`이 `default`가 아닌 값(`folderOpen`, 소스에만 보이는 `worktreeCreated` 등. 대소문자는 구분하지 않습니다)인 작업을 모두 알립니다. 근거에 작업 이름과 그 작업의 설정을 JSON 그대로 보여 드렸습니다. 운영체제별 블록(`windows`, `linux`, `osx`), 쓰는 셸(`options.shell`)도 그 안에 있습니다. 파일 맨 위에 작업에 적용되는 설정(`command`, `args`, `options`, 운영체제별 블록)이 있으면 `전역:` 뒤에 함께 보여 드립니다. dependsOn가 있으면 그 작업도 파일에서 확인하세요.

왜 확인해야 하나요?
VS Code 문서는 `folderOpen` 작업을 폴더가 열릴 때 실행되는 작업으로 설명합니다. `.vscode` 폴더는 저장소에 들어 있어서, 저장소를 받은 사람 모두에게 같은 작업이 따라갑니다. 작업은 내 컴퓨터에서 내 권한으로 실행되는 명령이므로, 모르는 사람이 보낸 저장소라면 무엇을 실행하는지 먼저 봐야 합니다.

실제로 실행되는 조건도 문서에 있습니다.
- 처음 여는 낯선 폴더는 제한 모드로 열리고, 문서는 신뢰하지 않은 작업공간에서는 자동 작업이 실행되지 않는다고 안내합니다.
- 작업공간을 신뢰한 뒤에는 설정 `task.allowAutomaticTasks`가 정합니다. 기본값 `off`는 자동 작업을 실행하지 않고, 해당 작업공간에서 아직 고르지 않았다면 한 번 허용할지 묻습니다. `on`이면 신뢰하는 작업공간에서 묻지 않고 실행합니다.

어떻게 하나요?
1. 근거에 보이는 명령이 무엇을 하는지 읽어 보세요. 내려받아 실행하는 명령, 알 수 없는 주소, 난독화된 코드가 보이면 실행하지 마세요.
2. 모르는 저장소는 제한 모드(신뢰하지 않음)로 여세요.
3. 신뢰하거나 자동 작업을 허용하기 전에 명령을 확인하세요.

이 점검은 파일의 글자만 읽고 아무것도 실행하지 않습니다. 명령이 해로운지 아닌지는 판단하지 않고, 자동 실행으로 설정되어 있다는 사실만 알려 드립니다. 근거가 "파일을 해석하지 못했습니다"로 나오면 파일이 깨졌거나 1MB보다 크거나 심볼릭 링크라서 읽지 않은 것이니 직접 열어 확인하세요.

참고로 `*.code-workspace` 파일의 `tasks`에서도 `folderOpen`이 동작하는지는 공식 문서로 확인하지 못해 이 점검은 보지 않습니다(확인 필요).

근거에 `****`가 보이면 비밀 값처럼 보이는 부분을 가린 것입니다. 실제 명령은 이 도구가 아닌 일반 텍스트 편집기로 파일을 열어 직접 확인하세요.
가리는 것은 gitleaks가 키로 알아본 값, URL 안의 비밀번호, 개인 키처럼 보이는 블록입니다. adk가 키로 알아보지 못한 값은 명령에 그대로 보입니다(예: `--password 값`). 그래서 이 리포트를 비밀 점검으로 쓰지 마세요. 비밀 값은 secrets 점검이 따로 찾습니다. `env` 안의 값은 이름에 token, password, key 같은 단어가 있으면 가립니다. 명령 문장이 섞여 있는 값은 키처럼 보여도 가리지 않습니다.
`-----BEGIN ... PRIVATE KEY-----`로 시작하는 블록은 진짜 키인지 따지지 않고 END 줄까지, END 줄이 없으면 그 값의 끝까지 통째로 가립니다. 그 자리에 가렸다는 문구가 나오고 등급은 "높음", 확신도는 "의심"이 됩니다. 이 안에 명령이 숨어 있을 수 있으니 파일을 직접 확인하세요.
근거가 길면 앞부분만 보여 주고 `… (잘림, 파일을 직접 확인하세요)`를 붙입니다. JSON 안에서 명령이 아닌 긴 값은 `…(잘림)`으로 줄입니다. 그때는 파일을 직접 열어 나머지를 확인하세요.
