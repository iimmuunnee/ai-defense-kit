이 컴퓨터의 GitHub CLI(`gh`) 설정 파일 `hosts.yml`에 토큰이 평문으로 저장되어 있습니다. 찾는 곳은 `GH_CONFIG_DIR`, 없으면 `XDG_CONFIG_HOME/gh`, 없으면 `~/.config/gh`이고, Windows에서는 `%APPDATA%\GitHub CLI`도 봅니다. 호스트마다 `oauth_token`, 그리고 여러 계정을 쓸 때의 `users` 아래 `oauth_token`이 비어 있지 않으면 알립니다. 근거에는 파일 경로와 호스트 이름(`hosts["github.com"].oauth_token` 같은)만 나오고, 계정 이름 대신 순서 번호를 씁니다.

왜 확인해야 하나요?
- 이 토큰은 대개 `repo`, `workflow` 권한을 가집니다. 파일을 읽은 프로그램이 저장소에 코드를 올리거나 워크플로를 바꿔, 배포 경로에 코드를 넣을 수 있습니다.
- `gh`의 기본 동작은 운영체제의 자격 증명 저장소에 토큰을 두는 것입니다. 이 파일에 토큰이 있다면 `--insecure-storage`로 로그인했거나, 저장소를 쓸 수 없는 환경이었다는 뜻입니다.

알리지 않는 것: 환경 변수 `GH_TOKEN`, `GITHUB_TOKEN`은 디스크에 저장된 값이 아니어서 보지 않습니다. 자격 증명 저장소에 들어 있는 토큰, `git`의 자격 증명 도우미가 저장한 값(`~/.git-credentials` 등)도 보지 않습니다.

`adk device check`에서는 `adk device init` 때 이미 있던 항목(번호, 파일, 항목 위치가 같은 것)을 "기준값에 있던 항목"으로 표시해 결과에 계속 적지만 종료 코드에는 반영하지 않습니다. init 뒤에 새로 생겼고 `adk device accept`로 받아들이지 않은 항목만 종료 코드를 1로 만듭니다. 기준값에는 위치만 적고 값은 적지 않습니다. 같은 위치에 값만 바뀐 토큰, 지운 뒤 같은 위치에 다시 생긴 토큰은 `accept`로 기준값에서 지우기 전까지 종료 코드에 반영되지 않습니다. `adk device`만 실행하면 모든 항목이 종료 코드에 반영됩니다.
