이 저장소의 `package.json`에 `npm install` 때 자동으로 실행되는 스크립트(`preinstall`, `install`, `postinstall`, `prepublish`, `preprepare`, `prepare`, `postprepare` 중 하나)가 있습니다. 근거에 스크립트 이름과 명령을 보여 드렸습니다.

왜 확인해야 하나요?
npm 문서의 생명주기 표에 따르면 `npm install`과 `npm ci`는 `preinstall`, `install`, `postinstall`, `prepublish`(폐기 예정), `preprepare`, `prepare`, `postprepare`를 차례로 실행합니다. `prepare`는 인자 없이 저장소 폴더에서 하는 `npm install`에서도 실행됩니다. 그래서 받은 저장소에서 설치만 해도 이 명령이 내 컴퓨터에서 내 권한으로 실행됩니다. 이 점검은 저장소 자신의 `package.json`만 읽으며, 설치될 의존성 패키지가 가진 스크립트는 보지 않습니다.

설치 때 실행되는 스크립트가 있다는 사실만으로 해로운지는 알 수 없어서 등급을 "낮음", 확신도를 "의심"으로 표시했습니다.

어떻게 하나요?
1. 근거의 명령이 무엇을 하는지 읽어 보세요. 내려받아 실행하는 명령, 알 수 없는 주소, 난독화된 코드가 보이면 설치하지 마세요.
2. 내용을 확인하기 전에는 설치하지 마세요. 꼭 해야 한다면 `npm install --ignore-scripts`처럼 `--ignore-scripts`를 붙이세요. 이 옵션을 주면 `package.json`의 스크립트를 실행하지 않습니다. 다만 `npm start`, `npm test`처럼 직접 실행하는 명령은 그대로 해당 스크립트를 실행합니다.

npm 11 문서에는 의존성 설치 스크립트용 정책(`allow-scripts` 등)도 있고, `--ignore-scripts`가 그보다 우선한다고 적혀 있습니다. 사용하는 npm 버전이 11이 아니면 이 정책 옵션은 적용되지 않을 수 있습니다(확인 필요).

이 점검은 파일의 글자만 읽고 아무것도 실행하지 않으며, 위에 적은 이름 밖의 스크립트는 보지 않습니다. 근거가 "파일을 해석하지 못했습니다"로 나오면 파일이 깨졌거나 1MB보다 크거나 심볼릭 링크라서 읽지 않은 것이니 직접 열어 확인하세요.

근거에 `****`가 보이면 비밀 값처럼 보이는 부분을 가린 것입니다. 실제 명령은 이 도구가 아닌 일반 텍스트 편집기로 파일을 열어 직접 확인하세요.
가리는 것은 gitleaks가 키로 알아본 값, URL 안의 비밀번호, 개인 키처럼 보이는 블록입니다. adk가 키로 알아보지 못한 값은 명령에 그대로 보입니다(예: `--password 값`). 그래서 이 리포트를 비밀 점검으로 쓰지 마세요. 비밀 값은 secrets 점검이 따로 찾습니다. `env` 안의 값은 이름에 token, password, key 같은 단어가 있으면 가립니다. 명령 문장이 섞여 있는 값은 키처럼 보여도 가리지 않습니다.
`-----BEGIN ... PRIVATE KEY-----`로 시작하는 블록은 진짜 키인지 따지지 않고 END 줄까지, END 줄이 없으면 그 값의 끝까지 통째로 가립니다. 그 자리에 가렸다는 문구가 나오고 등급은 "높음", 확신도는 "의심"이 됩니다. 이 안에 명령이 숨어 있을 수 있으니 파일을 직접 확인하세요.
근거가 길면 앞부분만 보여 주고 `… (잘림, 파일을 직접 확인하세요)`를 붙입니다. JSON 안에서 명령이 아닌 긴 값은 `…(잘림)`으로 줄입니다. 그때는 파일을 직접 열어 나머지를 확인하세요.
