이 저장소에 AI 코딩 도구가 읽는 설정 파일이 있고, 그 안에 도구가 실행할 수 있는 명령이나 연결할 주소가 적혀 있습니다. 근거에 서버 이름, 훅 이벤트 이름 또는 설정 이름과 그 설정을 JSON 그대로 보여 드렸습니다. 대상은 다음과 같습니다.
- `.mcp.json`, `.cursor/mcp.json`, `.vscode/mcp.json`의 `mcpServers`와 `servers`에서 `command`, `headersHelper`, `url` 중 하나가 있는 서버. 원격 서버는 명령이 없어도 어디로 연결하는지 보이도록 알립니다.
- `.claude/settings.json`, `.claude/settings.local.json`의 `hooks` 중 `type: command` 항목과 도우미 명령(`apiKeyHelper`, `awsAuthRefresh`, `awsCredentialExport`, `fileSuggestion`, `gcpAuthRefresh`, `otelHeadersHelper`, `statusLine`, `subagentStatusLine`).

 서버의 `env`와 `headers`는 이름만 보여 드리고, 값은 비밀이 들어 있을 수 있어 `****`로 바꿉니다.

왜 확인해야 하나요?
Claude Code 문서가 안내하는 내용은 다음과 같습니다.
- `.mcp.json` 서버: 대화형 세션에서는 프로젝트 서버를 쓰기 전에 승인을 묻습니다. 저장소가 커밋해 둔 자체 승인은 신뢰하지 않은 폴더에서 무시됩니다. 반면 `claude -p`나 Agent SDK처럼 질문을 띄울 수 없는 곳에서는 묻지 않고 프로젝트 서버를 불러옵니다.
- `.claude/settings.json`의 훅: 대화형 세션에서는 폴더 신뢰 대화상자를 수락하기 전까지 보류됩니다. `claude -p`와 SDK 세션은 대화상자를 보여 주지 않고 폴더를 신뢰한 것으로 취급하므로, 한 번도 신뢰하지 않은 폴더의 훅도 실행됩니다.
- `apiKeyHelper` 같은 도우미 명령: 부모 폴더만 신뢰했거나 `claude -p`, SDK로 돌릴 때도 쓰인다고 안내합니다. 실제로 언제 실행되는지는 도우미마다 다릅니다(자동 실행 여부 확인 필요).
- `statusLine`: 폴더 신뢰를 수락하기 전에는 실행하지 않는다고 안내합니다. `claude -p`에서 실행되는지는 문서로 확인하지 못했습니다(자동 실행 여부 확인 필요).
- `.mcp.json` 서버의 `headersHelper`: 임의의 셸 명령이며, 그 폴더의 신뢰를 수락한 뒤에만 실행한다고 안내합니다. `claude -p`와 SDK에서도 수락 전에는 실행하지 않습니다.
- `url`만 있는 서버: 명령을 실행하지 않고 그 주소로 연결합니다. 받은 코드와 대화 내용이 그쪽으로 갈 수 있으니 아는 주소인지 확인하세요.
- `.claude/settings.local.json`: 개인용 설정 파일로 안내합니다. 저장소에 커밋되어 함께 받은 파일도 같은 규칙으로 쓰이는지는 문서로 확인하지 못했습니다(자동 실행 여부 확인 필요).

VS Code 문서는 `.vscode/mcp.json`과 `.mcp.json`의 서버가 작업공간 신뢰를 따른다고 안내합니다. 제한 모드에서는 시작하지 않고, 신뢰한 작업공간에서는 따로 묻지 않고 시작될 수 있습니다. 기본 설정에서는 채팅 메시지를 보낼 때 새 서버를 시작할 수 있다고 적혀 있습니다. 그 밖의 시점과 Copilot 쪽 동작은 확인하지 못했습니다(자동 실행 여부 확인 필요).

Cursor의 `.cursor/mcp.json`은 서버가 언제 시작되는지 공식 문서로 확인하지 못했습니다(확인 필요). Cursor 문서는 MCP 연결에 사용자 승인이 필요하다고 안내하지만, 그 승인이 서버를 시작하기 전인지 도구를 부르기 전인지는 문서만으로 구분되지 않습니다.

어떻게 하나요?
1. 근거의 명령이 무엇을 하는지 읽어 보세요. 내려받아 실행하는 명령, 알 수 없는 주소, 난독화된 코드가 보이면 도구에서 승인하지 마세요.
2. 모르는 저장소에서 Claude Code를 `-p`로 쓰거나 신뢰를 누르기 전에 이 명령들을 확인하세요. Claude Code 문서는 낯선 저장소에서 `claude -p`를 돌리기 전에 `--setting-sources user`, `--bare`, `--settings '{"disableAllHooks": true}'` 중 하나를 쓰라고 권합니다.

이 점검은 파일의 글자만 읽고 아무것도 실행하지 않습니다. 명령이 해로운지는 판단하지 않아서 확신도를 "의심"으로 표시했습니다. 근거가 "파일을 해석하지 못했습니다"로 나오면 파일이 깨졌거나 1MB보다 크거나 심볼릭 링크라서 읽지 않은 것이니 직접 열어 확인하세요.

근거에 `****`가 보이면 비밀 값처럼 보이는 부분을 가린 것입니다. 실제 명령은 이 도구가 아닌 일반 텍스트 편집기로 파일을 열어 직접 확인하세요.
가리는 것은 gitleaks가 키로 알아본 값, URL 안의 비밀번호, 개인 키처럼 보이는 블록입니다. adk가 키로 알아보지 못한 값은 명령에 그대로 보입니다(예: `--password 값`). 그래서 이 리포트를 비밀 점검으로 쓰지 마세요. 비밀 값은 secrets 점검이 따로 찾습니다. `env` 안의 값은 이름에 token, password, key 같은 단어가 있으면 가립니다. 명령 문장이 섞여 있는 값은 키처럼 보여도 가리지 않습니다.
`-----BEGIN ... PRIVATE KEY-----`로 시작하는 블록은 진짜 키인지 따지지 않고 END 줄까지, END 줄이 없으면 그 값의 끝까지 통째로 가립니다. 그 자리에 가렸다는 문구가 나오고 등급은 "높음", 확신도는 "의심"이 됩니다. 이 안에 명령이 숨어 있을 수 있으니 파일을 직접 확인하세요.
근거가 길면 앞부분만 보여 주고 `… (잘림, 파일을 직접 확인하세요)`를 붙입니다. JSON 안에서 명령이 아닌 긴 값은 `…(잘림)`으로 줄입니다. 그때는 파일을 직접 열어 나머지를 확인하세요.
