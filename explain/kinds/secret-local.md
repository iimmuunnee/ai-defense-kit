git이 무시하도록 정해 둔 파일(`.gitignore`에 적힌 `.env` 등)에 비밀번호나 API 키 같은 값이 그대로 적혀 있습니다. git은 이 파일을 지금 관리하지 않고, 어느 브랜치나 태그의 기록에도 이 경로로 커밋된 적이 없습니다. 그래서 저장소를 올려도 이 파일은 함께 올라가지 않습니다.

키를 이런 파일에 두고 저장소에서 빼는 것은 흔히 권하는 방식입니다. 그래서 등급을 "참고"로 표시하고, `--fail-on`에는 걸리지 않습니다.

왜 알려 드리나요?
키는 이 컴퓨터에 글자 그대로 남아 있습니다. 폴더를 통째로 압축해 보내거나, 다른 곳에 복사하거나, git이 아닌 방법으로 공유하면 이 파일도 함께 나갑니다. `.gitignore`에서 이 줄을 지우거나 `git add -f`로 더하면 그때부터 저장소에 들어갑니다.

어떻게 하나요?
1. 이 파일이 공유하는 폴더나 압축 파일에 들어가지 않는지 확인하세요.
2. 이 키를 메신저나 메일 등으로 다른 곳에 보낸 적이 있다면, 해당 서비스에서 키를 폐기하고 새로 발급하세요.

이 점검이 확인한 것과 못 한 것
- git에 물어 세 가지를 확인했습니다. 이 파일을 무시하는지, 지금 관리하는지, 모든 브랜치와 태그의 기록에 이 경로로 커밋된 적이 있는지입니다.
- 다른 이름으로 커밋했다가 이름을 바꾼 경우, 다른 저장소나 다른 컴퓨터로 이미 복사된 경우는 알 수 없습니다.
- `--untrusted`로 점검할 때와 git 저장소가 아닐 때는 이 구분을 하지 않고 "높음"으로 알립니다.
